# ТЗ на MVP «Планировщик занятий репетитора»

Статус: **утверждён владельцем продукта, MVP реализован**.
Источник: `Планировщик занятий репетитора.docx`, `Проверка ИИ.docx`.
Область продукта: локальное расписание занятий частного репетитора.

## 1. Назначение

MVP проверяет гипотезу: репетитор, который держит всё расписание в одном месте,
перестаёт путаться в переносах и терять договорённости с учениками.

Результат MVP — недельный вид расписания, в котором занятие переносится или
отменяется одним действием, а по каждому ученику видно, сколько занятий оплачено,
сколько проведено и сколько осталось.

Целевой пользователь: частный репетитор с 5–30 учениками, который сейчас ведёт
расписание в заметках и чатах.

## 2. Паспорт проекта

- Уровень: Старт · Сервис
- Для кого: частный репетитор
- Результат: расписание занятий. Напоминания вынесены в P1 (см. A9)
- Ориентир по трудозатратам: 8–10 часов в неделю
- Пользовательская формулировка: «Как репетитор, я хочу видеть все занятия недели
  и быстро переносить их, чтобы не путаться в договорённостях»

## 3. Проблема клиента

Репетитор ведёт расписание в заметках и забывает о переносах. Договорённости
рассыпаются по мессенджерам, свободное время не видно, а по деньгам нет ответа
на вопрос «сколько ученик ещё должен».

## 4. Допущения и утверждённые решения

| # | Допущение | Решение |
|---|---|---|
| A1 | Формат — приложение, которым репетитор пользуется сам | Браузерная PWA: HTML/JS + `localStorage`, публикация на GitHub Pages |
| A2 | В системе один пользователь | Без аккаунтов, авторизации, ролей и прав |
| A3 | Ученик не входит в систему | Ученик — только запись в справочнике, без входа |
| A4 | Оплата выглядит как пакет занятий | Ученик оплачивает N занятий вперёд; баланс = оплачено − проведено |
| A5 | Баланс должен быть честным | Списывается только проведённое занятие; перенос и отмена баланс не трогают |
| A6 | У репетитора есть и регулярные, и разовые занятия | В MVP поддержаны оба типа: серия и разовое занятие |
| A7 | Неделя нужна стандартная | Границы недели и расчёт денег: Пн–Вс. Серия может занимать все 7 дней. Вид недели показывает рабочую неделю репетитора Пн–Суб, воскресенье — отдельным блоком (решение владельца продукта от 2026-09-27, §15) |
| A8 | Ставка — цена одного занятия | Длительность в часах не используется. `durationMin` хранится только для отображения интервала и защиты от пересечений. `rate` участвует в недельном итоге: сумма к оплате и долг |
| A9 | В брифе результатом заявлены «расписание и напоминания» | Напоминания вынесены в P1/P2, в MVP не реализуются. Паспорт приведён в соответствие |
| A10 | Данные не должны уходить в сеть | Хранение полностью локальное, без сервера и внешних интеграций |
| A11 | Контакт ученика один | Одно текстовое поле: телефон, Telegram или почта |
| A12 | Серию нужно поддерживать без ручного создания каждого занятия | Горизонт генерации серии — 4 недели вперёд, продление вручную |
| A13 | Расписание смотрят со смартфона | Интерфейс проектируется под мобильный: работа одной рукой, экран от 320 px |

Допущения A4, A8 и A9 подтверждены владельцем продукта 2026-09-26 вместе с
решениями из §15: деньги в недельном итоге считаются по ставке, напоминания
остаются вне MVP.

## 5. Пользователи и сценарии

### 5.1. Пользователь

Репетитор — единственный пользователь MVP. Ведёт справочник учеников,
расписание и учёт предоплаты.

### 5.2. Основной сценарий

1. Репетитор добавляет ученика: имя, предмет, контакт, ставка.
2. Создаёт занятие: разовое или серию с регулярностью.
3. Открывает недельный вид и видит все занятия недели.
4. Переносит или отменяет занятие.
5. Открывает карточку занятия и пишет, что прошли, и домашнее задание.
6. Отмечает занятие проведённым, предоплата списывается.
7. После перезагрузки страницы все данные остаются на месте.

### 5.3. Дополнительные сценарии

- закрыть серию, чтобы новые занятия не создавались;
- записать оплату: пакет занятий на конкретную дату;
- посмотреть историю переносов занятия;
- отключить ученика от показа в неделе без удаления истории;
- переключиться на прошлую или будущую неделю;
- достроить серию на следующие недели.

## 6. Модель данных

### 6.1. Student — ученик

| Поле | Тип | Обяз. | Назначение |
|---|---|:---:|---|
| `id` | UUID | да | Идентификация |
| `name` | строка | да | Имя ученика |
| `subject` | строка | да | Предмет |
| `contact` | строка | нет | Телефон, Telegram или почта |
| `rate` | число > 0 | да | Цена одного занятия |
| `timezone` | значение справочника часовых поясов | нет | Часовой пояс ученика; справочная величина, на расписание не влияет |
| `goal` | строка ≤ 120 | нет | Цель занятий, например «Подготовка к ОГЭ» |
| `color` | значение палитры | да | Визуальная идентификация в неделе |
| `active` | булево | да | Показывается ли в недельном виде |
| `createdAt` | дата/время | да | Порядок и аудит |

Часовой пояс ученика — справочное поле. Даты, неделя и время занятий считаются в
локальном часовом поясе репетитора, `timezone` ничего не сдвигает (ТЗ §7 BR-17).

### 6.2. LessonSeries — серия занятий

Серия описывает повторяющееся расписание ученика: список **слотов**, у каждого
слота свой день недели, время и длительность. Поэтому одна серия может давать
любое число занятий в неделю (FR-2.4A).

| Поле | Тип | Обяз. | Назначение |
|---|---|:---:|---|
| `id` | UUID | да | Идентификация |
| `studentId` | UUID | да | Связь с учеником |
| `slots` | массив слотов, 1–7 | да | Недельный рисунок: у каждого слота своё время |
| `startsOn` | `YYYY-MM-DD` | да | Дата первого занятия серии |
| `endsOn` | `YYYY-MM-DD` | нет | Ограничение конца серии |
| `active` | булево | да | Генерирует ли серия новые занятия |
| `createdAt` | дата/время | да | Порядок и аудит |

#### 6.2.1. SeriesSlot — слот серии

| Поле | Тип | Обяз. | Назначение |
|---|---|:---:|---|
| `weekday` | 1–7 | да | День недели (1 = Пн) |
| `startTime` | `HH:MM` | да | Время начала |
| `durationMin` | число > 0 | да | Длительность, по умолчанию 60 |

Два слота с одинаковым `weekday` в одной серии невозможны: иначе в один день
у ученика окажется два занятия и инвариант «одно занятие на пару
`(seriesId, date)`» перестанет выполняться. Если два занятия в один день нужны,
создаются две серии.

### 6.3. Lesson — занятие

| Поле | Тип | Обяз. | Назначение |
|---|---|:---:|---|
| `id` | UUID | да | Идентификация |
| `studentId` | UUID | да | Связь с учеником |
| `date` | `YYYY-MM-DD` | да | Календарная дата занятия |
| `startTime` | `HH:MM` | да | Время начала |
| `durationMin` | число > 0 | да | Длительность |
| `status` | перечисление | да | `planned` / `done` / `cancelled` / `moved` |
| `isTrial` | булево | да | Пробное занятие: не приносит денег и не списывает баланс (BR-16) |
| `topicNote` | строка | нет | Что прошли на занятии |
| `homework` | строка | нет | Домашнее задание |
| `seriesId` | UUID или null | нет | Ссылка на серию; у разового занятия пуст |
| `movedToLessonId` | UUID или null | нет | Куда перенесено занятие |
| `movedFromLessonId` | UUID или null | нет | Откуда занятие перенесено |
| `createdAt` | дата/время | да | Порядок и аудит |
| `updatedAt` | дата/время | да | Порядок и аудит |

Статусы: `planned` — запланировано, `done` — проведено,
`cancelled` — отменено, `moved` — перенесено.

### 6.4. Payment — оплата (пополнение пакета)

| Поле | Тип | Обяз. | Назначение |
|---|---|:---:|---|
| `id` | UUID | да | Идентификация |
| `studentId` | UUID | да | Связь с учеником |
| `lessonsCount` | число > 0 | да | Сколько занятий оплачено |
| `paidAt` | `YYYY-MM-DD` | да | Дата оплаты |
| `comment` | строка | нет | Комментарий к оплате |
| `createdAt` | дата/время | да | Порядок и аудит |

### 6.5. Вычисляемые значения

- **Баланс ученика** = `Σ Payment.lessonsCount` − `count(Lesson where status = done и isTrial = false)`
- **Итог недели** = количество запланированных, проведённых, отменённых и
  перенесённых занятий за выбранную неделю, суммарный остаток предоплаты по
  ученикам недели, **сумма к оплате** и **долг**
- **Сумма к оплате за неделю** = `Σ rate` по занятиям недели со статусом
  `planned` или `done` и `isTrial = false`. Занятия со статусом `cancelled` и
  `moved` не учитываются, поэтому перенос попадает в сумму ровно один раз — в
  неделе своей новой даты. Пробные занятия не учитываются: они видны в
  количествах, но не приносят денег (BR-16)
- **Долг** = `Σ |balance| × rate` по ученикам недели с отрицательным остатком
  предоплаты

Баланс, сумма к оплате и долг — вычисляемые значения, а не сохранённые поля.
Это исключает рассинхронизацию денег и расписания. Суммы округляются до целых
рублей, валюта отображения — ₽, формат `1 200 ₽`.

Ограничения целостности:

- пара `(seriesId, date)` уникальна — серия не может дать два занятия в один день,
  поэтому в одной серии не больше одного слота на день недели;
- у разового занятия `seriesId` пуст;
- `movedToLessonId` и `movedFromLessonId` ссылаются только на существующие занятия
  и описывают один перенос в обе стороны;
- дата занятия не раньше `startsOn` своей серии и не позже `endsOn`, если он задан;
- хранится календарная дата, а не произвольный timestamp.

## 7. Бизнес-правила

- **BR-1.** Занятие нельзя создать без ученика, даты и времени. Пустое поле →
  форма не отправляется, показывается понятное сообщение.
- **BR-2.** Слот занят. Два занятия в одну дату с пересекающимися интервалами
  создать нельзя: репетитор один и физически не может вести два занятия.
  Касание границы интервалов пересечением не считается.
- **BR-2A.** Пересечение, которое уже лежит в данных, приложение находит и
  показывает, но не правит. Отменённое занятие слот освобождает и пересечением
  не считается, перенесённое — считается, как и при создании (BR-4, BR-9).
  Автоматическая отмена, сдвиг или любая другая правка таких занятий запрещены:
  решение принимает репетитор, переносом или отменой лишнего занятия.
- **BR-3.** Генерация серии. Серия создаёт занятия на 4 недели вперёд от `startsOn`
  по каждому слоту: у слота своя неделя, своё время начала и своя длительность.
  Одна серия даёт от одного до семи занятий в неделю. Дни до `startsOn` не создаются.
  Действие «достроить» продлевает горизонт без дублей.
- **BR-3A.** В серии не больше одного слота на день недели. Повтор дня недели
  отклоняется с сообщением, лишний слот удаляется; два занятия в один день
  создаются двумя сериями.
- **BR-4.** Перенос — это перемещение, а не копия. Исходное занятие получает
  статус `moved`, остаётся в своей ячейке недели в приглушённом виде, а новое
  занятие создаётся в целевой дате со связями `movedToLessonId` и
  `movedFromLessonId`. Так выполняется критерий «перенос сразу отражается
  в недельном виде».
- **BR-5.** Перенос сохраняет остальные поля: ученик, время начала, длительность,
  заметка и ДЗ переходят в новое занятие.
- **BR-6.** Перенос не меняет баланс.
- **BR-7.** Перенос в прошлое запрещён: целевая дата не может быть раньше сегодняшней.
- **BR-8.** Отмена необратима. Занятие в статусе `cancelled` нельзя снова перевести
  в `done`. Для возврата работы нужно создать новое занятие.
- **BR-9.** Отмена не меняет баланс.
- **BR-10.** Списание баланса. Перевод занятия в `done` уменьшает баланс ровно на 1.
  Повторный перевод в `done` невозможен, списание не может произойти дважды.
- **BR-11.** Проведённое занятие при нулевом балансе допустимо. Баланс уходит в минус
  и показывается как долг, ученик помечается предупреждением. Операция не блокируется.
- **BR-12.** Статусы необратимы по направлению: `cancelled` и `moved` — конечные.
  `planned` → `done` | `cancelled` | `moved`.
- **BR-13.** Закрытие серии. `active = false` останавливает генерацию; уже созданные
  занятия сохраняются, их статусы и заметки можно менять.
- **BR-14.** Отключение ученика. `active = false` убирает ученика из недельного вида,
  но сохраняет занятия, заметки, оплаты и историю. Итоги дня и недели при этом
  тоже перестают его считать, чтобы числа совпадали с тем, что показано (FR-3.1D).
- **BR-15.** Баланс ученика всегда пересчитывается из оплат и проведённых занятий.
  Изменение исходных данных и перезагрузка дают один и тот же результат.
- **BR-16.** Пробное занятие бесплатно. Занятие с `isTrial = true` не входит в
  сумму к оплате и при переводе в `done` не уменьшает баланс ученика. При этом оно
  остаётся полноценным занятием: видно в количествах итога, его можно перенести и
  отменить, и перенос и отмена пробного не меняют баланс.
- **BR-17.** Часовой пояс ученика справочный. Даты, границы недели и время
  занятий считаются в локальном часовом поясе репетитора; `timezone` ученика не
  сдвигает расписание и не участвует в вычислениях.

## 8. Функциональные требования

### FR-1. Справочник учеников

- **FR-1.1** Создание ученика: имя, предмет, ставка, цвет — обязательны;
  контакт необязателен.
  КА: создание «Иван, Физика, 1200 ₽, контакт не указан» → ученик появляется
  в списке.
- **FR-1.2** Имя обязательно и не может состоять только из пробелов.
  КА: отправка формы с пустым именем отклоняется с сообщением.
- **FR-1.3** Ставка — положительное число.
  КА: ставка 0 или отрицательная отклоняются.
- **FR-1.4** Редактирование полей ученика.
  КА: изменение имени, предмета, контакта и ставки сохраняется после перезагрузки.
- **FR-1.5** Карточка ученика показывает предмет, контакт, ставку, баланс
  «оплачено X − проведено Y = осталось Z», последние занятия и историю оплат.
  КА: после двух проведённых занятий при оплаченных четырёх карточка показывает
  «оплачено 4 − проведён 2 → осталось 2».
- **FR-1.6** Отключение ученика без удаления истории.
  КА: отключённый ученик отсутствует в недельном виде, его прошлое занятие
  и оплаты остаются в карточке.
- **FR-1.7** Предупреждение об исчерпанной предоплате.
  КА: при балансе 0 рядом с именем ученика в неделе видна метка
  «предоплата исчерпана».
- **FR-1.8** Цвет выбирается из фиксированной палитры, произвольный hex не принимается.
  КА: значение вне палитры отклоняется.
- **FR-1.9** Цель занятий — необязательная строка до 120 символов.
  КА: сохраняется цель «Подготовка к ОГЭ», она видна в карточке ученика и
  переживает перезагрузку; пустая цель не мешает создать ученика.
- **FR-1.10** Часовой пояс ученика выбирается из справочника, по умолчанию не задан.
  КА: выбранный пояс сохраняется и показывается в карточке ученика, при этом
  расписание остаётся прежним (BR-17).

### FR-2. Создание занятия

- **FR-2.1** Создание разового занятия: ученик, дата, время, длительность.
  КА: занятие появляется в неделе, содержащей его дату.
- **FR-2.1a** Разовое занятие можно пометить пробным.
  КА: включённый флажок «Пробное занятие» даёт занятие с меткой «пробное», которое
  не входит в сумму к оплате и не списывает баланс (BR-16). Занятия серии пробными
  не бывают, поэтому в блоке серии флажка нет.
- **FR-2.2** Валидация обязательных полей.
  КА: невозможно создать занятие без ученика и без времени — форма не отправляется,
  показывается сообщение.
- **FR-2.3** Защита от пересечения интервалов.
  КА: попытка создать занятие с 16:00 на 90 минут при существующем занятии
  с 16:30 отклоняется.
- **FR-2.4** Создание серии: ученик, список слотов (день недели, время,
  длительность), дата старта, необязательная дата окончания.
  КА: серия со вторника 18:00 и стартом 01.09.2026 → создаются занятия по вторникам
  на 4 недели вперёд.
- **FR-2.4A** Одна серия даёт любое число занятий в неделю.
  В форме серии список слотов: у каждого свои день недели, время и длительность,
  слоты добавляются и удаляются. Не больше одного слота на день недели.
  КА: слоты Пн 18:00, Ср 18:00, Сб 12:00 со стартом 28.09.2026 дают 12 занятий
  за 4 недели, по три в неделю; повтор в тот же день недели отклоняется с
  сообщением, а лишний слот удаляется кнопкой.
- **FR-2.4B** Число занятий в неделю и расписание видны до сохранения.
  КА: в форме показано «3 занятия в неделю: Пн 18:00 – 19:00, Ср 18:00 – 19:00,
  Сб 12:00 – 13:00», в карточке ученика и в списке «Ученики» — тот же рисунок.
- **FR-2.5** Соблюдение `startsOn` и `endsOn`.
  КА: занятия серии не создаются раньше даты старта и позже даты окончания.
- **FR-2.6** Повторный запуск генерации не создаёт дублей.
  КА: после `buildSeries` для уже сгенерированного диапазона количество занятий
  не увеличивается.
- **FR-2.7** «Достроить серию» продлевает горизонт.
  КА: после действия появляются занятия следующих недель без дублей.
- **FR-2.8** Закрытие серии.
  КА: после закрытия новые занятия не создаются, существующие остаются в неделе
  и редактируются.
- **FR-2.8A** Расписание задаётся для каждого ученика отдельно.
  Из карточки ученика создаётся серия с уже выбранным учеником, а в списке
  «Ученики» видно расписание каждого.
  КА: у первого ученика серия Пн 18:00, у второго Сб 10:00; в списке видно
  «Расписание: Пн 18:00 – 19:00» и «Расписание: Сб 10:00 – 11:00», занятия
  не смешиваются.
- **FR-2.9** Отказ сохранения не теряет введённое.
  Форма остаётся открытой, введённые значения на месте, причина отказа
  показана в самой форме и называет, кто занимает слот.
  КА: серия второго ученика на занятые 18:00 не сохраняется, форма остаётся
  открытой с выбранным днем недели и временем, текст «Занято: 24 сентября,
  18:00 – 19:00 у ученика Иван. Выберите другое время или день недели.»;
  после смены времени та же форма сохраняет серию.

### FR-3. Недельный вид (рабочая неделя репетитора)

- **FR-3.1** Рабочая неделя репетитора Пн–Суб показывается вертикальным
  списком дней с заголовком диапазона дат: заголовок дня, под ним его занятия
  по времени. Воскресенье в список не входит.
  КА: открывается неделя текущей даты, каждый день недели — отдельный блок с
  полным названием дня и датой, занятия идут под ним по возрастанию времени;
  на широком экране блоки дней стоят в две колонки, на узком — в одну.
- **FR-3.1A** Воскресенье показывается отдельным блоком под списком рабочей недели.
  КА: занятия воскресенья видны и не теряются, в том числе когда их несколько;
  если занятий нет, блок сообщает, что воскресенье свободно.
- **FR-3.1B** Занятия в блоке воскресенья входят в итог недели.
  КА: количества, сумма к оплате и долг считаются по всей неделе Пн–Вс, включая
  воскресенье, независимо от того, в какой части экрана показано занятие.
- **FR-3.1C** В неделе видны время занятия, ученик, предмет и статус; заметка
  и ДЗ доступны в карточке занятия, а не в неделе.
  КА: строка занятия в неделе читается на 320 px, например «18:00 – 19:00
  Свелана, английский, запланировано»; полные данные открываются по нажатию.
- **FR-3.1D** Итог недели и итог дня считают только тех учеников, чьи занятия
  показаны в сетке. Занятия закрытого ученика в неделю не попадают (BR-14),
  поэтому их нет и в количествах, и в сумме к оплате, и в долге.
  КА: у закрытого ученика неделя показывает ноль занятий и `0 ₽`, как в сетке.
- **FR-3.1E** Пустая неделя объясняет, почему занятий не видно.
  КА: если занятия на неделе есть только у закрытого ученика, подсказка сообщает,
  что его занятия скрыты; если есть более позднее занятие, подсказка предлагает
  кнопку «Перейти к занятию <дата>», которая открывает ту неделю.
- **FR-3.1F** Карточка ученика показывает ближайшее занятие, а не последнее по дате.
  КА: подпись «Ближайшее занятие» соответствует первому занятию не раньше сегодняшнего
  дня; если таких занятий нет, подпись меняется на «Последнее занятие».
- **FR-3.1G** Нижняя панель вкладок занимает одну строку и не накрывает содержимое.
  КА: все три вкладки видны в одной строке, а под списком учеников кнопка
  «Добавить ученика» доступна без прокрутки под панель.
- **FR-3.1H** Список занятий в карточке ученика содержит занятия этого ученика
  и начинается с ближайших, а не с самых дальних. Список разделён на «Ближайшие»
  и «Прошедшие», показывает общее число занятий и раскрывается по кнопке
  «Показать все» без ограничения.
  КА: в списке первым идёт ближайшее занятие не раньше сегодняшнего дня, при
  большом количестве занятий дальние не вытесняют ближайшие, а полный список
  доступен по кнопке.
- **FR-3.1I** На вкладке «День» список занятий идёт первым, итог дня — под ним.
  КА: открыв день, сразу видны ученики и время их занятий, а блок итога
  «Всего / Запланировано / Проведено / К оплате за день» расположен ниже списка.
- **FR-3.1J** Пересечения, уже лежащие в данных, показываются списком и не
  правятся молча: баннер на любой вкладке со счётчиком и кнопкой «Показать
  список», в шторке — дата, время, ученик и статус каждого занятия в пересечении;
  нажатие на строку открывает карточку занятия, где его переносят или отменяют.
  КА: при двух занятиях 28.09 в 18:00 баннер сообщает о пересечении и открывает
  список из двух строк; нажатие открывает карточку занятия, перенос или отмена
  одного из них убирают пересечение и баннер; когда пересечений нет, баннера нет.
- **FR-3.2** Переключение недель: предыдущая, следующая, «эта неделя».
  КА: переход на следующую неделю меняет заголовок и состав занятий.
- **FR-3.3** Занятие показывает время, ученика, предмет и цвет ученика.
  КА: карточка занятия различима по времени и имени.
- **FR-3.4** Пустое состояние объясняет, что делать, и даёт действие.
  КА: если учеников нет, вместо пустых дней показано одно сообщение
  «Расписание пока пустое» и кнопка «Добавить ученика», которая открывает форму
  ученика прямо с недели. Если ученики есть, а занятий в этой неделе нет, дни
  остаются видимыми с подписью «Нет занятий».
- **FR-3.5** Отменённое занятие визуально отличается и не зависит только от цвета.
  КА: у отменённого занятия есть отдельный паттерн и подпись «отменено».
- **FR-3.6** Перенесённое занятие остаётся в исходной ячейке в приглушённом виде.
  КА: занятие 15.09 числится 15.09 со статусом «перенесено», а его новое
  местоположение — в дате переноса; видны обе карточки.
- **FR-3.7** Итог недели виден на экране: число занятий и сумма к оплате.
  КА: панель показывает «запланировано N, проведено M, отменено K», остаток
  предоплаты по ученикам недели, сумму к оплате в рублях и отдельно долг,
  если баланс отрицательный.
- **FR-3.8** Мобильный вид без горизонтального переполнения на 320 px.
  КА: неделя прокручивается вертикально, основные действия остаются достижимыми.
- **FR-3.9** Сортировка занятий внутри дня по времени начала.
  КА: занятия выводятся от раннего к позднему.

### FR-3A. Дневной вид

- **FR-3A.1** Приложение открывается на вкладке «День», а не на неделе.
  КА: первый экран после запуска — дневной вид с сегодняшней датой.
- **FR-3A.2** Три вкладки: «День», «Неделя», «Ученики».
  КА: переключение между ними не сбрасывает выбранную дату.
- **FR-3A.3** Навигация по дням: предыдущий день, следующий день, «Сегодня»
  и полная дата в заголовке.
  КА: переход на следующий день меняет заголовок и состав занятий.
- **FR-3A.4** Занятия дня показываются теми же карточками, что и в неделе:
  время, ученик, предмет, цвет, статус, заметка и ДЗ.
  КА: карточка из дневного вида открывает ту же карточку занятия.
- **FR-3A.5** Занятия дня отсортированы по времени начала.
  КА: занятие в 19:00 идёт после занятия в 10:00.
- **FR-3A.6** Итог за день: количество занятий и сумма к оплате за день.
  КА: в итоге дня видно «Занятия: 2» и сумму по ставкам учеников; пробное
  занятие в сумму не входит, но в количестве остаётся (BR-16).
- **FR-3A.7** Пробное занятие помечено текстом, а не только цветом.
  КА: на карточке пробного занятия есть подпись «пробное» (NFR-6).
- **FR-3A.8** Ближайшее занятие сегодняшнего дня отмечено.
  КА: первое ещё не прошедшее запланированное занятие помечено «следующее».
- **FR-3A.9** Пустое состояние объясняет, что делать, и даёт действие.
  КА: при отсутствии учеников показано сообщение «Расписание пока пустое» и
  кнопка «Добавить ученика»; при наличии учеников, но отсутствии занятий в
  выбранный день — «Нет занятий» с подсказкой создать занятие на этот день.
- **FR-3A.10** Создание занятия из дневного вида подставляет выбранный день.
  КА: нажатие «+» открывает форму, где дата разового занятия равна дате дня.
- **FR-3A.11** Дневной вид без горизонтального переполнения на 320 px.
  КА: дневной вид прокручивается вертикально, длинные имена учеников
  переносятся, а не растягивают карточку.

### FR-4. Карточка занятия

- **FR-4.1** Содержит ученика, предмет, дату, интервал, статус, заметку и ДЗ.
  КА: все поля видны и заполняются.
- **FR-4.2** Заметка и ДЗ — два независимых поля.
  КА: сохранение текста в «что прошли» не влияет на «домашнее задание» и наоборот.
- **FR-4.3** Сохранение заметки и ДЗ без перезагрузки.
  КА: после сохранения текст виден в неделе и после перезапуска.
- **FR-4.4** Действие «Перенести»: выбор новой даты и времени.
  КА: перенос 15.09 18:00 → 17.09 19:00 оставляет карточку 15.09 в статусе
  «перенесено» и создаёт занятие 17.09 19:00 с тем же учеником.
- **FR-4.5** Действие «Отменить» с подтверждением.
  КА: после отмены занятие остаётся в неделе с пометкой «отменено».
- **FR-4.6** Действие «Проведено».
  КА: после нажатия статус меняется, баланс уменьшается на 1.
- **FR-4.7** История переносов видна в карточке.
  КА: у перенесённого занятия указаны исходная дата и новая дата переноса.
- **FR-4.8** Конечные статусы нельзя отменить обратным действием.
  КА: у занятия в статусе «отменено» или «перенесено» действие «Проведено»
  недоступно с понятным объяснением.
- **FR-4.9** Занятие с неизвестным учеником не открывается как рабочая карточка.
  КА: битая ссылка показывает состояние ошибки, а не пустую форму.

### FR-5. Учёт предоплаты

- **FR-5.1** Запись оплаты: количество занятий и дата.
  КА: оплата 4 занятий 01.09.2026 увеличивает баланс ученика на 4.
- **FR-5.2** Количество оплаченных занятий — положительное целое.
  КА: 0, дробное и отрицательное значения отклоняются.
- **FR-5.3** Дата оплаты не может быть в будущем.
  КА: выбор завтрашней даты отклоняется с сообщением.
- **FR-5.4** История оплат видна в карточке ученика с датами и комментариями.
  КА: две оплаты отображаются обе.
- **FR-5.5** Баланс пересчитывается, а не хранится.
  КА: изменение исходных данных и перезагрузка дают один и тот же баланс.
- **FR-5.6** Отмена и перенос не меняют баланс.
  КА: ученик с балансом 4, одно занятие отменено и одно перенесено → баланс 4.
- **FR-5.7** Проведённое занятие при нулевом балансе разрешено, баланс уходит в минус
  и показывается как долг.
  КА: баланс 0, отмечаем занятие проведённым → баланс −1, видно «долг: 1 занятие».

### FR-6. Персистентность и целостность данных

- **FR-6.1** Все изменения сохраняются сразу и переживают перезагрузку страницы.
  КА: добавленное занятие остаётся после перезагрузки.
- **FR-6.2** Перенос сразу отражается в недельном виде без ручного обновления.
  КА: перенос отражается в том же экране.
- **FR-6.3** Схема хранилища версионирована, при изменении выполняется миграция.
  Текущая версия — 3. Миграция 2 → 3 переносит поля серии `weekday`, `startTime`
  и `durationMin` в один слот `slots[0]`, поэтому ранее созданные серии и их
  занятия остаются рабочими без действий пользователя.
  КА: хранилище версии 2 с серией «вторник 18:00» после загрузки показывает
  серию с одним слотом, её занятия остаются в неделе, повторная генерация
  не создаёт дублей.
- **FR-6.4** Повреждённые или неподдерживаемые данные не удаляются молча:
  исходный JSON сохраняется в резервный слот, интерфейс показывает понятное
  состояние ошибки.
  КА: при повреждённом хранилище данные не пропадают безвозвратно.
- **FR-6.5** Недоступное хранилище не оставляет активными действия, которые
  нельзя сохранить.
  КА: при недоступном хранилище форма создания недоступна, объяснение видно.
- **FR-6.6** В исходном коде нет ключей, токенов и персональных данных.
- **FR-6.7** Данные можно сохранить в файл и вернуть из файла. Экспорт доступен
  всегда, в том числе когда хранилище недоступно, повреждено или его версия не
  распознана: тогда выгружается исходный JSON как есть. Формат файла совпадает с
  форматом хранилища, поэтому выгруженный файл восстанавливается без
  преобразований.
  КА: репетитор выгружает файл, приложение сообщает, что файл создан, а файл
  открывается и читается как JSON.
- **FR-6.8** Восстановление из файла — полная замена данных с предпросмотром и
  подтверждением. До применения показывается состав файла и предупреждение о
  замене. Перед заменой текущие данные копируются в резервный слот и остаются
  доступны для выгрузки, поэтому восстановление обратимо. Битый файл, файл из
  более новой версии приложения и файл больше 5 МБ отклоняются с понятным
  объяснением, текущие данные при этом не меняются.
  КА: выбранный файл показывает состав до применения, после подтверждения данные
  из файла видны в приложении, прежние данные доступны для выгрузки, а отказ
  ничего не меняет.

### FR-7. Качество и выпуск

- **FR-7.1** Есть команды `dev`, `lint`, `typecheck`, `test`, `build`.

- **FR-7.4** `AGENTS.md` описывает источник истины, инварианты и проверки.
- **FR-7.5** Приложение опубликовано и доступно по ссылке.
- **FR-7.6** В репозитории есть скриншоты ключевых экранов на синтетических данных.
- **FR-7.7** Приложение устанавливается на телефон как PWA и работает офлайн.

## 9. Нефункциональные требования

- **NFR-1.** Мобильный интерфейс, пригодный для работы одной рукой: основные
  действия доступны большим пальцем, интерактивные элементы имеют достаточный
  размер касания.
- **NFR-2.** На ширине 320 px основные экраны не имеют горизонтального переполнения.
  Это относится ко всем трём вкладкам: «День», «Неделя» и «Ученики».
- **NFR-3.** Все интерфейсные тексты на русском языке.
- **NFR-4.** Операция в неделе (создание, перенос, отмена) визуально отражается
  мгновенно, без перезагрузки.
- **NFR-5.** Данные хранятся локально и не отправляются по сети.
- **NFR-6.** Состояние занятия различимо без зависимости только от цвета.
- **NFR-7.** Ошибки хранения обрабатываются без молчаливой потери данных.
- **NFR-8.** Код содержит unit-, integration- и UI-тесты доменной логики
  и основных пользовательских потоков.
- **NFR-9.** Окружение: современный браузер на Windows 10/11, мобильный браузер
  на Android и iOS.
- **NFR-10.** Сборка публикуется статически; серверная часть отсутствует.
- **NFR-11.** Приложение работает офлайн после первого открытия.

## 10. Вне скоупа MVP

- аккаунты, авторизация, роли и права;
- вход ученика и его личный кабинет;
- сервер, синхронизация между устройствами, офлайн-синхронизация;
- уведомления и напоминания (P1);
- внешние интеграции: календарь Google, мессенджеры, платёжные системы;
- автоматический сбор ДЗ нейросетью как обязательная функция;
- экспорт и импорт данных, резервное копирование;
- несколько репетиторов, командная работа;
- печать расписания;
- учёт расходов, зарплата, отчёты по доходу;
- публичный доступ по ссылке с редактированием.

Отдельно зафиксировано как сознательно не взятое при сравнении с аналогом
(`teacherplanner.ru`, изучен 2026-09-26): перерыв внутри занятия, время
напоминания, темы урока и проблемы ученика, группы учеников, месячный и дневной
календари без недели, часовой пояс со сдвигом расписания, доходы и расходы,
аналитика, Telegram/VK/push-уведомления, аккаунты и кабинет ученика, тренажёры
ОГЭ и ЕГЭ. Из этого списка в работу взяты только дневной вид, цель ученика,
часовой пояс без сдвига и пробное занятие — см. §15.

## 11. Критерии готовности MVP

Приёмочный сценарий. Все шаги выполняются последовательно:

1. Создать ученика: Иван, Физика, контакт, ставка 1200, синий цвет.
   КА: ученик появился в справочнике.
2. Записать оплату 4 занятия с датой сегодня.
   КА: баланс ученика 4.
3. Создать серию: вторник, 18:00, 60 минут, старт сегодня, без даты окончания.
   КА: в неделе видны занятия по вторникам.
4. Создать разовое занятие в четверг 19:00 на 90 минут.
   КА: занятие появилось в четверг.
5. Попытаться создать занятие без выбора ученика и без времени.
   КА: форма не отправляется, показано сообщение.
6. Попытаться создать второе занятие с пересекающимся интервалом.
   КА: отклонено с понятным сообщением.
7. Перезагрузить страницу.
   КА: ученик, оплата, серия и разовое занятие на месте.
8. Перенести занятие вторника 18:00 на среду 19:00.
   КА: занятие осталось во вторнике в статусе «перенесено», новое занятие
   появилось в среду, в карточке видна история переноса.
9. Отменить разовое занятие в четверге.
   КА: оно осталось в неделе с отметкой «отменено», визуально отличается,
   баланс не изменился.
10. Отметить одно занятие проведённым и записать заметку и ДЗ.
    КА: статус изменился, баланс стал 3, заметка и ДЗ сохранились отдельно.
11. Проверить недельный итог.
     КА: видны количества запланированных, проведённых, отменённых и
     перенесённых занятий, остаток предоплаты, сумма к оплате за неделю
     в рублях, а при отрицательном балансе — долг.
     Отменённое и перенесённое занятия в сумму к оплате не входят.
12. Провести занятие при нулевом балансе.
     КА: операция разрешена, баланс ушёл в минус и показан как долг.
13. Создать разовое занятие и пометить его пробным.
     КА: на карточке есть текстовая метка «пробное».
14. Отметить пробное занятие проведённым.
     КА: баланс не изменился, пробное не попало в сумму к оплате ни за день,
     ни за неделю; обычное занятие рядом в сумму входит.
15. Перенести и отменить пробное занятие.
     КА: поведение не отличается от обычного занятия, баланс не изменился.
16. Открыть вкладку «День».
     КА: приложение стартует на «Дне», видны занятия выбранного дня по времени,
     итог за день и метка «следующее» на ближайшем занятии; переключение
     «День» → «Неделя» не сбрасывает дату.
17. Закрыть серию и нажать «достроить» у другой.
     КА: закрытая серия не создаёт новых занятий, открытая продлилась без дублей.
18. Повредить данные в хранилище и перезагрузить.
     КА: показано состояние ошибки, исходный JSON сохранён в резервном слоте.
19. Загрузить данные версии 1 схемы.
     КА: состояние открывается без ошибки, новые поля получают пустые значения
     по умолчанию, а существующие занятия, оплаты и серии сохраняются.
20. Открыть вкладку «Неделя».
     КА: сетка показывает шесть рабочих дней Пн–Суб, в колонке видно время
     занятия и ученика, воскресенье вынесено отдельным блоком под сеткой, а его
     занятия входят в итог недели.
21. Перенести занятие из воскресенья в субботу.
     КА: в воскресенье осталось исходное занятие со статусом «перенесено», в
     субботе появилось новое, в сумму к оплате перенесённое не входит.
22. Запустить `lint`, `typecheck`, `test`, `build`.
     КА: все команды успешны.
23. Открыть приложение на телефоне, установить как PWA, работать офлайн.
     КА: приложение открывается без сети, дневной и недельный виды и карточка
     занятия читаемы, горизонтальной прокрутки нет.
24. Войти во вкладку «Ученики», взять первого ученика и создать ему серию,
     затем то же самое для второго.
     КА: форма серии открывается с уже выбранным учеником, в списке видно
     «Расписание: …» у каждого, занятия серий не смешиваются.
25. Создать второму ученику серию на то же время, что и первому.
      КА: серия не создаётся, форма остаётся открытой с введёнными значениями,
      показано, кто и когда занимает этот слот; после смены времени серия
      сохраняется.
26. Создать серию с несколькими днями: Пн 18:00, Ср 18:00, Сб 12:00.
      КА: в форме показано «3 занятия в неделю», после сохранения за 4 недели
      создано 12 занятий, по три в неделю, у каждого дня своё время; повтор
      дня недели в форме отклоняется.
27. Открыть хранилище версии 2 (серия с одним днём) и загрузить приложение.
      КА: серия показана со слотом, её занятия остались в неделе, «достроить»
      не создаёт дублей.
28. Выгрузить данные в файл на вкладке «Ученики».
      КА: создан файл с именем `tutor-scheduler-ГГГГ-ММ-ДД-ЧЧММ.json`, его
      содержимое совпадает с состоянием приложения, а импорт этого же файла
      возвращает те же данные.
29. Выбрать для восстановления файл с другими данными.
      КА: до подтверждения видно, сколько в файле учеников, серий, занятий и
      оплат, и предупреждение, что текущие данные будут заменены; после
      подтверждения приложение показывает данные из файла.
30. Восстановить данные в непустое приложение.
      КА: прежние данные не потеряны — они сохранены в резервном слоте и
      выгружаются отдельной кнопкой; отмена восстановления ничего не меняет.
31. Выбрать для восстановления битый файл и файл из более новой версии.
      КА: показано понятное объяснение, текущие данные не изменились.
32. Открыть приложение с повреждённым хранилищем и выгрузить данные.
      КА: экспорт доступен и выгружает исходный JSON как есть.

## 12. План проверки

### 12.1. Unit-тесты домена

- валидация обязательных полей занятия и ученика;
- отказ при пустом имени и при неположительной ставке;
- пересечение интервалов: полное, частичное, касание границы, без пересечения;
- генерация серии: границы 4-недельного горизонта, `startsOn`, `endsOn`,
  повторный вызов без дублей;
- слоты серии: несколько дней в одной серии, даты по возрастанию и без дублей,
  у каждого дня своё время, от 1 до 7 занятий в неделю;
- слоты серии: повтор дня недели отклоняется, пустой список слотов и неверное
  время или длительность отклоняются;
- пересечение по слоту: отказ называет занятый слот, отмена слота освобождает
  дату, перенесённое занятие слот не освобождает;
- поиск уже существующих пересечений: два занятия в один слот находятся, касание
  границы и отменённое занятие пересечением не считаются, найденное пересечение
  отклоняется при создании нового занятия на том же времени;
- закрытие серии останавливает генерацию;
- перенос: правильные связи, сохранение полей, запрет переноса в прошлое,
  запрет переноса в занятие с пересечением;
- отмена: перевод в конечный статус, невозможность повторного `done`;
- баланс: оплата увеличивает, `done` уменьшает, отмена и перенос не меняют,
  баланс уходит в минус, пересчёт после перезагрузки;
- недельные границы: Пн–Вс, первая и последняя неделя месяца, годовая граница,
  високосный год;
- недельный итог: подсчёт по трём статусам;
- дневной вид совпадает с неделей в части общих сумм;
- рабочая неделя Пн–Суб: шесть дат, воскресенье отдельно, границы недели и
  `summarizeWeek` по-прежнему Пн–Вс;
- занятия воскресенья видны в отдельном блоке и входят в итог недели; перенос из
  воскресенья оставляет исходное занятие в своём блоке, а сумму не меняет.
- отказ сохранения серии называет ученика, который занимает слот (FR-2.9);
- перерисовка экрана не закрывает открытую форму: отказ сохраняет введённые
  значения (FR-2.9);
- пробное занятие: `isTrial` по умолчанию `false`, не оплачивается, не списывает
  баланс, но учитывается в количествах дня и недели, переносится и отменяется как
  обычное;
- ближайшее занятие: первое ещё не начавшееся в статусе `planned`;
- цель ученика обрезается пробелами, длиннее 120 символов и неизвестный часовой
  пояс отклоняются;
- экспорт: сериализация состояния и обратный разбор совпадают, имя файла содержит
  локальную дату и время, порядок ключей фиксирован;
- разбор файла восстановления: корректный файл даёт состав, битый JSON, пустой
  файл, файл из более новой версии и файл больше 5 МБ отклоняются с объяснением;
- миграция файла восстановления: серия версии 2 из файла приходит с одним слотом.

### 12.2. Integration-тесты хранилища

- запись и чтение всех четырёх сущностей;
- персистентность после перезапуска;
- версия схемы и миграция;
- миграция 2 → 3: `weekday`, `startTime` и `durationMin` серии переносятся
  в `slots[0]`, занятия и остальные сущности не меняются;
- обработка повреждённых данных и отсутствующего хранилища;
- сохранение исходного JSON в резервный слот;
- недоступное хранилище: форма недоступна, объяснение видно;
- целостность связей: удалённый ученик, потерянная серия, оборванная связь переноса.
- восстановление: новое состояние записывается целиком, прежний JSON уходит в
  резервный слот, резервный слот не перетирается при запуске со сломанными
  данными, ошибка записи оставляет прежнее состояние.

### 12.3. UI-тесты

- создание ученика и проверка формы, включая `goal` и `timezone`;
- создание разового занятия и серии, флажок «пробное»;
- форма серии: добавление и удаление слотов, сводка «N занятий в неделю»,
  отказ на повторе дня недели;
- неделя с занятиями, переключение недель, пустая неделя;
- рабочая неделя: шесть колонок Пн–Суб, блок воскресенья, карточка в колонке
  показывает время и ученика, перенос из воскресенья;
- день с занятиями выбранной даты, переключение дней, метка «следующее»,
  переход «День» → «Неделя» без сброса даты;
- перенос и отмена с обновлением дня и недели;
- сохранение заметки и ДЗ, их независимость;
- отметка «проведено» с пересчётом баланса;
- панель итога дня и недельного итога;
- мобильные состояния на 320 px;
- баннер пересечений и список в шторке: счётчик, строки с датой, временем, учеником
  и статусом, переход из строки в карточку занятия, исчезновение баннера после
  переноса или отмены одного из занятий (FR-3.1J);
- состояния ошибки без потери введённых данных;
- экспорт: кнопка в подвале «Учеников» и в баннере сломанных данных, файл
  создаётся с ожидаемым именем;
- восстановление: предпросмотр состава файла, отмена ничего не меняет,
  подтверждение заменяет данные, битый файл показывает объяснение и сохраняет
  текущие данные.

## 14. Риски и открытые вопросы

### 14.1. Риски

1. **Серии — основной источник багов.** Пересечения, отмена перенесённого занятия,
   генерация вперёд и закрытие серии требуют обязательного покрытия тестами.
2. **ИИ в клиентской PWA требует API-ключа**, а ключ в `localStorage` хранится
   в открытом виде. Решение владельца продукта от 2026-09-26: ИИ-модуль не
   входит в MVP и остаётся выключенным, ДЗ репетитор пишет руками, сеть не
   используется. Если модуль вернут в скоуп, ключ должен вводить сам
   репетитор, а без ключа ручной ввод не блокируется (A1 + FR-7.8).
3. **Персональные данные учеников** (имя, контакт) хранятся в открытом
   `localStorage`. Нужно предупреждение в README и в пустом состоянии.
4. **Смена origin** (домен, протокол, порт, браузер) создаёт отдельное хранилище —
   прежние данные не появятся автоматически. Отдельный пункт в README.
5. **Согласие владельца продукта.** Требования, помеченные в §4 как допущения,
   действуют только после подтверждения.

### 14.2. Открытые вопросы

1. Нужна ли отмена в один клик или с подтверждением? Решение: с подтверждением.
2. Нужен ли одновременный просмотр на двух вкладках? Решение: нет, в P2.
3. Нужна ли сортировка учеников в неделе? Решение: по времени начала занятия.
4. Нужна ли отметка «пропущено учеником»? Решение: нет, достаточно `cancelled`.
5. Нужен ли прогноз дохода за месяц? Решение: нет, в P2.
6. Локализация: только русский, подтверждено (NFR-3).
7. Нужна ли печать расписания или экспорт в PDF? Решение: нет, в P2.
8. Напоминания: в брифе они есть в строке «Результат», но отсутствуют в
   «Составе MVP». Решение владельца продукта от 2026-09-26: оставить вне MVP,
   P1. Push-уведомления не добавлять без отдельного решения по scope.
9. Что считать «суммой к оплате» в итоге недели? Решение владельца продукта
   от 2026-09-26: стоимость неотменённых занятий недели плюс отдельная строка
   долга, а не остаток предоплаты в рублях.
10. В каком формате хранить копию и что делать с текущими данными при
    восстановлении? Решение владельца продукта от 2026-09-28: JSON того же вида,
    что лежит в хранилище, восстановление — полная замена с предпросмотром и
    подтверждением, прежние данные автоматически уходят в резервный слот.
    Слияние с текущими данными, шифрование файла, автокопии по расписанию и
    хранение копий внутри приложения — вне MVP (FR-6.7, FR-6.8).

## 16. Источник требований

Формулировки взяты из `исходные данные, Планировщик занятий репетитора.docx`
(паспорт, цель, задача клиента, пользователи, главный сценарий, состав MVP,
экраны, данные, критерии готовности) и `Проверка ИИ.docx` (этапы приёмки).

Исходный бриф не имеет идентификаторов требований, поэтому настоящий документ
нормализует его в рабочую спецификацию. Новые продуктовые и технические решения
должны добавляться сюда и в журнал решений, чтобы не терять трассируемость.
