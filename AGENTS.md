# AGENTS.md

## Назначение проекта

Репозиторий содержит спецификацию и локальное браузерное PWA-приложение для
расписания занятий частного репетитора. Главный пользовательский сценарий:
добавить ученика, создать занятие или серию, увидеть неделю, перенести или
отменить занятие, отметить проведённым и записать заметку с домашним заданием.

Приложение работает полностью локально, основной сценарий рассчитан на телефон.
Пользователь один: репетитор. Аккаунтов, авторизации и сервера нет.

## Текущее состояние

- Спецификация `ТЗ_MVP.md` утверждена владельцем продукта.
- MVP реализован целиком: домен (`src/domain/`), хранилище (`src/storage/`),
  стор (`src/app/`), интерфейс (`src/ui/`), точка входа `src/main.ts`.
- Команды проекта существуют: `dev`, `lint`, `typecheck`, `test`, `build`,
  `preview`, `build:standalone`.
- Тесты: 200 проверок в 8 файлах (`tests/`), включая приёмочный сценарий
  `ТЗ_MVP.md` §11, мобильные требования §9 и guard самодостаточного
  `index.html`.
- Два входа в приложение. Точка входа vite — `app/index.html` (корень vite
  `app/`, обвязка `app/main.ts` ведёт к `src/main.ts`), из неё собирается
  `dist/index.html` с PWA. Корневой `index.html` — сгенерированная
  самодостаточная сборка для запуска из папки двойным щелчком; править её
  вручную нельзя, она обновляется `npm run build`. В папочной версии не
  работают service worker, офлайн и установка PWA, а её данные не общие с
  веб-версией.
- Публикация: `README.md` и workflow
  `.github/workflows/deploy-pages.yml`; приложение опубликовано как
  `https://ei2405ei-art.github.io/tutor-scheduler/`, репозиторий
  `ei2405ei-art/tutor-scheduler`. Прод-base относительный (`./`), поэтому
  переименование репозитория не требует правок в коде.
- В PowerShell выполнять npm через `npm.cmd`.
- Скриншоты интерфейса: `docs/screenshots/`, сняты в мобильном Chrome на
  живом деплое, демо-данные вымышленные. Переснимаются скриптом
  `scripts/screenshots.mjs` через `npm run screenshots`; системный Chrome,
  браузер не скачивается. Скрипту нужен `playwright-core`, которого нет в
  зависимостях намеренно: перед запуском `npm i -D playwright-core`. В CI
  не выполняется. В приложении всего три вкладки, «День», «Неделя» и
  «Ученики», часть снимков — они же с открытой нижней шторкой.
- Снимки в `docs/screenshots/` устарели: они сделаны до появления вкладки
  «День» и стартового экрана «День». Не выдавать их за текущий интерфейс и
  не переснимать без согласования с владельцем продукта.
- Не выполнено: прогон приёмки по чек-листу `Проверка ИИ.docx` вручную

- Стек, зафиксированный в `ТЗ_MVP.md` §4: браузерная PWA, HTML/JS,

- Кейс оформлен в этом же репозитории: `README.md` в формате кейса,

## Рабочий процесс

1. Прочитать `ТЗ_MVP.md` и определить затронутую часть MVP.
2. Проверить структуру проекта и существующие соглашения.
3. Уточнить неоднозначные доменные правила до реализации.
4. Реализовывать минимальный вертикальный сценарий, а не отдельный экран.
5. Добавлять тесты вместе с изменением доменной логики и хранилища.
6. Обновлять документацию при изменении модели данных, схемы хранилища
   или пользовательского поведения.
7. Перед завершением запускать все доступные проверки и сообщать, какие команды
   отсутствуют.

## Обязательные предметные инварианты

- Занятие нельзя создать без ученика, даты и времени.
- Два занятия в одну дату с пересекающимися интервалами создать нельзя.
  Касание границы интервалов пересечением не считается.
- Для пары `(seriesId, date)` существует не более одного занятия.
- Дни до `startsOn` серии и после `endsOn` не создаются.
- Повторный запуск генерации серии не создаёт дублей.
- Перенос перемещает занятие: исходное получает статус `moved` и остаётся
  в своей ячейке недели, новое создаётся в целевой дате.
- Перенос и отмена не меняют баланс предоплаты.
- Перевод в `done` списывает ровно одно занятие и только один раз.
- Статусы `cancelled` и `moved` конечные: из них нельзя перейти в `done`.
- Перенос в прошлое запрещён.
- Дата оплаты не может быть в будущем, количество оплаченных занятий —
  положительное целое.
- Баланс — вычисляемое значение, а не сохранённое поле.
- Пробное занятие (`isTrial`) не входит в сумму к оплате и не списывает баланс
  при статусе `done`. В количествах итога недели оно остаётся. Перенос, отмена и
  остальные статусы работают как у обычного занятия, баланс не трогают.
- Часовой пояс ученика — справочное поле. Даты, неделя и время занятий считаются
  в локальном часовом поясе репетитора, `timezone` ничего не сдвигает.
- Сумма к оплате за неделю и долг — вычисляемые значения по ставке ученика.
  `cancelled` и `moved` в сумму не входят, поэтому перенос попадает в сумму
  ровно один раз — в неделе новой даты. Суммы округляются до целых рублей,
  формат `1 200 ₽` без `Intl` (см. `src/domain/money.ts`).
- Схема хранилища версии 3. Серия хранит массив `slots` (1–7 слотов), у каждого
  слота свой день недели, время и длительность. Два слота одного дня в серии
  невозможны, для двух занятий в один день создаются две серии. Старые поля
  `weekday`/`startTime`/`durationMin` переносятся в `slots[0]` миграцией 2 → 3.
- Хранятся календарные даты, а не произвольные timestamp.
- Границы недели и расчёт денег — Пн–Вс. Вкладка «Неделя» показывает рабочую
  неделю Пн–Суб вертикальным списком дней: заголовок дня с датой, под ним занятия
  по времени; на широком экране блоки дней в две колонки. Воскресенье вынесено
  отдельным блоком под списком. В занятии недели видны время, ученик, предмет
  и статус. На вкладке «День» список занятий идёт раньше итога дня.
  Занятия воскресенья входят в итог недели и не теряются при переносе: исходное
  остаётся в своём блоке со статусом `moved`.
- Повреждённые данные не удаляются молча, исходный JSON сохраняется
  в резервный слот.

## Правила реализации

- Следовать стеку и существующим конфигурациям из `ТЗ_MVP.md` §4 и §9.
- Правки страницы вносить в `app/index.html`. Корневой `index.html`
  генерируется, руками его не править; после изменений в `src/` выполнить
  `npm run build`, иначе папочная версия останется старой.
- Не переносить точку входа обратно в корень: имя выходного файла задаётся
  путём относительно `root: 'app'`, и `dist/index.html` нужен манифесту,
  precache и `navigateFallback`.
- Доменная логика не зависит от DOM и вынесена в `src/domain/`.
- Схема хранилища версионирована; изменения требуют миграции.
- Интерфейс проектируется под телефон: работа одной рукой, корректная
  вёрстка от 320 px, состояние занятия различимо без зависимости только от цвета.
- Не добавлять backend, аккаунты, роли, аналитику, уведомления или внешние
  интеграции без отдельного решения по scope.
- Не добавлять секреты, токены и реальные персональные данные учеников
  в исходный код, фикстуры и скриншоты.
- Пользовательские значения выводить безопасно, не через небезопасную сборку HTML.
- Не удалять исторические данные без явного пользовательского действия.
- Не менять публичное поведение без обновления `ТЗ_MVP.md` и тестов.
- ИИ-модуль по умолчанию выключен, не должен требовать ключа и блокировать
  ручное заполнение домашнего задания.
- Не создавать коммиты без отдельного явного запроса пользователя.

## Проверки

Запускать перед передачей результата:

- `lint`;
- `typecheck`;
- `test`;
- `build`;
- `npm audit --omit=dev`.

Перед передачей результата проверить:

- доменные тесты серий, переносов, статусов и баланса;
- сохранение данных после перезапуска;
- приёмочный сценарий из `ТЗ_MVP.md` §11;
- что корневой `index.html` открывается из папки и проходит тот же сценарий
  по `file://` (в нём нет service worker и офлайна — это ожидаемо);
- мобильные состояния на ширине 320 px;
- пустые состояния и состояния ошибок;
- отсутствие лишних файлов, секретов и реальных персональных данных.

## Определение готовности задачи

Задача считается завершённой, если изменение соответствует `ТЗ_MVP.md`,
покрыто релевантными тестами, все доступные проверки проходят, а изменения
не содержат несогласованных изменений scope.
